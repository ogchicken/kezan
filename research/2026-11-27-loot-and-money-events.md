# Loot and money events research, 27 November 2026

Desk research for the gold-per-hour tracker: whether the loot and money data it needs is readable by addons on Forever (plan section 6, question 1), whether the events exist, what their payloads look like, what working Forever addons use, and the other open questions in section 6.

On sources: the firmest source is Blizzard's own generated API documentation for the Forever client, mirrored in the `forever` branch of [Gethe/wow-ui-source](https://github.com/Gethe/wow-ui-source/tree/forever) at build 1.60.1 (71139), committed 25 November 2026. It declares every documented event and function together with its secret-value attributes. Where this note says "Retail" it means the `live` branch at 12.1.5 (70961). Functions the documentation does not cover were checked in [Ketho/BlizzardInterfaceResources](https://github.com/Ketho/BlizzardInterfaceResources/tree/forever) (`forever` branch, 1.60.1 (70938)), which lists the client's globals, events, CVars and global strings. Addon source code shows what working addons do, but most of the "chat is secret in instances" comments in it are defensive guesses, not observations; this note says which is which. Items marked *unverified* need the in-game probe at the end.

Permalinks below use these commits: wow-ui-source `forever` [`d9c22e3`](https://github.com/Gethe/wow-ui-source/commit/d9c22e32cb240afb82bb2ecefbb78ef935333f59), `live` [`ab5cb85`](https://github.com/Gethe/wow-ui-source/commit/ab5cb850a3f65e742959e379c4689353a2f4549f); BlizzardInterfaceResources `forever` [`e230342`](https://github.com/Ketho/BlizzardInterfaceResources/commit/e230342a476eb4ef484ba7b34adc0da6ecc6acc1).

## 1. Secret values and loot and money data

### What the rules cover

- Secret values restrict what tainted (addon) code can do with a value: it can store it, pass it on, concatenate or `string.format` it and ask its `type`, but cannot compare it, do arithmetic on it, take its length, index it or use it as a table key. [Warcraft Wiki: Secret Values](https://warcraft.wiki.gg/wiki/Secret_Values)
- The generated docs mark secrecy per API: `SecretReturns` (always secret), `ConditionalSecret` (sometimes), and predicates such as `SecretWhenInCombat` or `SecretInChatMessagingLockdown` on a function or event. `SecretArguments = "AllowedWhenUntainted"` only says whether a function accepts secret *arguments*; it says nothing about its returns. `NeverSecret = true` on a payload field keeps that field readable even when the event is secret. [Secret Values](https://warcraft.wiki.gg/wiki/Secret_Values), [SecretPredicatesDocumentation.lua (Forever)](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/SecretPredicatesDocumentation.lua)
- The chat predicate, word for word on Forever: `SecretInChatMessagingLockdown`: "Guarded APIs and events produce secret values when encounter, challenge mode, or PvP match addon restrictions are in effect, and when the player is on a communication-restricted map such as a dungeon or raid." [SecretPredicatesDocumentation.lua#L65](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/SecretPredicatesDocumentation.lua#L65). The text is identical on Retail.
- Restrictions are typed: `Enum.AddOnRestrictionType` is Combat, Encounter, ChallengeMode, PvPMatch, Map and Chat. `C_RestrictedActions.GetAddOnRestrictionState(type)`, `C_RestrictedActions.IsAddOnRestrictionActive(type)` and the event `ADDON_RESTRICTION_STATE_CHANGED(type, state)` report them, and `C_ChatInfo.InChatMessagingLockdown()` reports the chat one. Per Blizzard, the event fires "the immediate moment before a restriction activates, or after it deactivates". [RestrictedActionsConstantsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/RestrictedActionsConstantsDocumentation.lua), [RestrictedActionsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/RestrictedActionsDocumentation.lua), [ChatInfoDocumentation.lua#L293](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua#L293), [Blizzard post of 8 December, Patch 12.0.0/API changes/notes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes/notes)
- History: the Midnight alpha post (1 October 2025) made all chat in instances secret. Blizzard then narrowed this to active keystones, PvP matches and encounters (11 October), and later "declassified a number of chat message events (for things like GUILD_ITEM_LOOTED, which are not exploit risks)" (10 December). [Patch 12.0.0/API changes/notes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes/notes) The predicate text above shows dungeon and raid maps are back in scope for the chat types that carry it.
- Forever: "The addon disarmament changes introduced in Midnight, including secrets, will also be active in Forever." [Patch 1.60.1/API changes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes) The tags below are the same on Forever and Retail unless stated.

### The APIs Kezan needs

|---|---|---|

| `CHAT_MSG_MONEY` | same as `CHAT_MSG_LOOT` | readable in every documented context |

| `CHAT_MSG_SYSTEM`, `CHAT_MSG_OPENING`, `CHAT_MSG_SKILL`, `CHAT_MSG_SAY`, `PARTY`, `RAID`, `WHISPER`, ... (47 chat events) | `SecretInChatMessagingLockdown = true` | secret in dungeons, raids, encounters, keystones and PvP matches |
| `GetMoney()` | none (its neighbours in the file carry `SecretWhenUnitStatsRestricted`) | readable |
| `PLAYER_MONEY` | none, no payload | readable |
| `LOOT_READY`, `LOOT_OPENED`, `LOOT_SLOT_CLEARED`, `LOOT_CLOSED`, `LOOT_ITEM_ROLL_WON` | none | readable |

- So by Blizzard's own declaration, loot and money chat, the wallet and the loot events stay readable in dungeons, raids, combat and encounters. The same declaration makes `CHAT_MSG_SYSTEM` secret in dungeons, which matters because quest money ("Received %s.") arrives there (section 3).
- *Unverified:* whether the client actually behaves as declared. The fields without `NeverSecret` are the ones that would turn secret if a predicate applied; with no predicate on the event, none is documented to apply. No primary source shows `CHAT_MSG_LOOT` text arriving secret.
- *Unverified:* the loot-window functions. They exist on Forever ([GlobalAPI.lua#L5572-L5575](https://github.com/Ketho/BlizzardInterfaceResources/blob/e230342a476eb4ef484ba7b34adc0da6ecc6acc1/Resources/GlobalAPI.lua#L5572-L5575)) and Forever's own loot window uses `GetNumLootItems`, `GetLootSlotInfo`, `GetLootSlotLink` and `GetLootSlotType` ([LootFrame.lua](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/LootFrame.lua), loaded on Forever through `[Family]\LootFrame.lua` in [Blizzard_UIPanels_Game.toc#L127](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_UIPanels_Game/Blizzard_UIPanels_Game.toc#L127)), but undocumented functions carry no secrecy tags. `GetLootSourceInfo` returns creature GUIDs, and Blizzard said "Access to creature unit names, GUIDs, and IDs are secret while in an instance" ([12.0.0 notes, 27 October](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes/notes)), so expect its GUIDs to be secret in dungeons. Forever also obfuscates the server and spawn IDs in creature and game object GUIDs ([Patch 1.60.1/API changes](https://warcraft.wiki.gg/wiki/Patch_1.60.1/API_changes), Beta 5).
- A real in-client report: AnotherLedger v0.4.3 fixed "a 'secret string value' Lua error" when "Looting in dungeons or in combat"; the fixing commit says the secret values were unit names, GUIDs and tooltip lines, not chat text. [CHANGELOG.md#L76-L80](https://github.com/mxhes/AnotherLedger/blob/10a14ae4f0ad8ce477565f008d112b140440f328/CHANGELOG.md#L76-L80), [commit 5a54551](https://github.com/mxhes/AnotherLedger/commit/5a54551477)

## 3. Payload shapes

- `CHAT_MSG_LOOT` and `CHAT_MSG_MONEY` share the chat payload: `text, playerName, languageName, channelName, playerName2, specialFlags, zoneChannelID, channelIndex, channelBaseName, languageID, lineID, guid, bnSenderID, isMobile, isSubtitle, hideSenderInLetterbox, suppressRaidIcons, discordInfo`. [ChatInfoDocumentation.lua#L1813-L1866](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua#L1813-L1866), [Warcraft Wiki: CHAT_MSG_LOOT](https://warcraft.wiki.gg/wiki/CHAT_MSG_LOOT)
- The wiki calls `guid` the "Sender's Unit GUID" and `playerName2` "The target name when there are two users involved". It does not say whether, for loot lines, these name the looter. *Unverified;* no addon read for this note relies on them.
- Every Forever loot addon read for this note tells own loot from a groupmate's by matching the text against the `_SELF` global strings. Forever's enUS values ([enUS.lua](https://github.com/Ketho/BlizzardInterfaceResources/blob/e230342a476eb4ef484ba7b34adc0da6ecc6acc1/Resources/GlobalStrings/enUS.lua)):
  - own: `LOOT_ITEM_SELF` "You receive loot: %s", `LOOT_ITEM_SELF_MULTIPLE` "You receive loot: %sx%d", `LOOT_ITEM_PUSHED_SELF` "You receive item: %s", `LOOT_ITEM_PUSHED_SELF_MULTIPLE` "You receive item: %sx%d", `LOOT_ITEM_CREATED_SELF(_MULTIPLE)` "You create: %s." / "%sx%d.", `LOOT_ITEM_BONUS_ROLL_SELF`, `LOOT_ITEM_REFUND(_MULTIPLE)`;
  - others: `LOOT_ITEM` "%s receives loot: %s.", `LOOT_ITEM_MULTIPLE`, `LOOT_ITEM_PUSHED(_MULTIPLE)` "%s receives item: %s.";
  - money: `YOU_LOOT_MONEY` "You loot %s", `LOOT_MONEY_SPLIT` "Your share of the loot is %s.", `YOU_LOOT_MONEY_GUILD`, `LOOT_MONEY_SPLIT_GUILD`, `LOOT_MONEY` "%s loots %s." (someone else);
  - rolls: `LOOT_ROLL_YOU_WON` "|HlootHistory:%d|h[Loot]|h: You won: %s", `LOOT_ROLL_WON` "... %s won: %s", and `_NO_SPAM_` variants per roll type;
  - quests: `ERR_QUEST_REWARD_MONEY_S` "Received %s.".
- Note that the self strings have no trailing full stop on Forever, while the wiki's example line ends in "x2.". A pattern anchored with `$` should allow an optional full stop. *Unverified* which form the client sends.
- Roll wins: `LOOT_ITEM_ROLL_WON(itemLink, rollQuantity, rollType, roll, upgraded)` exists, and ForeverLootRolls parses the roll lines (`LOOT_ROLL_*`) from `CHAT_MSG_LOOT` on Forever ([Parser.lua](https://github.com/sudo-elmo/ForeverLootRolls/blob/HEAD/Parser.lua)). On Retail a won roll produces both "You won: X" and a separate "You receive loot: X" line, so counting only the `LOOT_ITEM_SELF*` lines avoids double counting. *Unverified* on Forever.
- Gathering: Time Is Money attributes herbs, ore and leather from `CHAT_MSG_LOOT` lines to the gathering cast before them, which implies gathering produces `CHAT_MSG_LOOT` on Forever ([Core.lua#L987-L1000](https://github.com/RyrinsRealm/Time-Is-Money/blob/591eeecb1f1bcbbc3ac0a547f6a9b5b4b1cc7da0/Core.lua#L987-L1000)). Addon evidence only.
- Containers (clams, lockboxes): they open the loot window with `LOOT_OPENED(autoLoot, isFromItem)` where `isFromItem` is true; Forever's loot frame plays the container sound on it ([LootFrame.lua#L128-L138](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/LootFrame.lua#L128-L138), [LootDocumentation.lua#L218-L227](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/LootDocumentation.lua#L218-L227)). That taking items from it produces `CHAT_MSG_LOOT` "You receive loot" lines, as from a corpse, is *unverified*. Opening a lockbox with a skill posts `CHAT_MSG_OPENING`, which is chat-lockdown secret.
- Quest money: comes as `ERR_QUEST_REWARD_MONEY_S` on `CHAT_MSG_SYSTEM`, not `CHAT_MSG_MONEY`; CleanerLootMessages filters it on `CHAT_MSG_SYSTEM` ([CleanerLootMessages.lua#L139-L161](https://github.com/luttman/CleanerLootMessages/blob/8fdc1191922311f198c6ca86cd0c9e8167008390/CleanerLootMessages.lua#L139-L161)). `QUEST_TURNED_IN(questID, xpReward, moneyReward)` also carries the amount ([QuestLogDocumentation.lua#L1394-L1404](https://github.com/Gethe/wow-ui-source/blob/d9c22e32cb240afb82bb2ecefbb78ef935333f59/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua#L1394-L1404)). Addon evidence; *unverified* in game.
- Vendor sales produce no chat line, only `PLAYER_MONEY`; Time Is Money books a positive wallet change while a merchant is open as a sale, minus coin `CHAT_MSG_MONEY` just reported ([Core.lua#L1520-L1535](https://github.com/RyrinsRealm/Time-Is-Money/blob/591eeecb1f1bcbbc3ac0a547f6a9b5b4b1cc7da0/Core.lua#L1520-L1535)). Addon evidence; *unverified* in game.
- `PLAYER_MONEY` has no payload; read `GetMoney()`. `PLAYER_INTERACTION_MANAGER_FRAME_SHOW(type)` and `_HIDE(type)` take an `Enum.PlayerInteractionType`, one event pair for merchant, mail, trade and auction house windows.

- The two lines that ship working loot and money tracking with no secret checks at all are Time Is Money (`f:RegisterEvent("CHAT_MSG_LOOT")`, [Core.lua#L1425](https://github.com/RyrinsRealm/Time-Is-Money/blob/591eeecb1f1bcbbc3ac0a547f6a9b5b4b1cc7da0/Core.lua#L1425)) and ForeverLooter. That is good evidence the events exist and fire, and some evidence that the text is readable in the open world.
- The "secret in instances" comments are guesses. ForeverLootTracker: "In instances Forever may deliver chat as secret values" ([Capture.lua#L745](https://github.com/Westfall-Digital/ForeverLootTracker/blob/05276f486637aed24ddeb63cfb60ee7d4703a849/Capture.lua#L745)). AnotherLedger's chat guard (commit "skip secret chat texts and numbers instead of erroring", 25 November) is defensive, and its own fix commit calls `issecretvalue` "UNVERIFIED". The one observed error was on unit names and GUIDs (section 1). No issue tracker of these addons reports a secret `CHAT_MSG_LOOT` or `CHAT_MSG_MONEY` text.
- Midas and Countinghouse are auction house tools; no public loot-tracking source for them was found on GitHub.
- Pattern most addons converge on: chat events as the main path, with `issecretvalue` guards. The more careful ones keep a loot-window or bag-diff fallback. The plan's fallback (diffing `GetMoney()` and bags) is what ForeverLootTracker and Gathercraft actually do.

## 5. Plan open question 2: a plain `Kezan.toc` with 16001

- The client classifies an addon as out of date only when its `## Interface` doesn't match the client's; Forever's is 16001. It looks for a TOC with its game-type suffix (`_Forever`, `_Camelot`), then the family suffix (`_Mainline`), then the plain file. [Warcraft Wiki: TOC format](https://warcraft.wiki.gg/wiki/TOC_format)
- ForeverPlusPlus, tested on the live client: "Ship one plain `ForeverPlusPlus.toc` with `## Interface: 16001`. That works." [forever-api.md#L46](https://github.com/xIGBClutchIx/ForeverPlusPlus/blob/6b98426f7b8132bf0dfb3e8620484ae9621e0054/docs/forever-api.md#L46)
- Seven of the addons above ship only a plain TOC at 16001 (ForeverLoot, ForeverLooter, GoldPerHour, AnotherLedger, Gathercraft, ForeverLootRolls, LootLog).
- Verdict: yes. One caution: never add a `Kezan_Mainline.toc` for Retail later without also adding `Kezan_Forever.toc`, because the family suffix beats the plain file on Forever.

## 6. Plan open question 3: TSM price sources on Forever

- TSM's website refuses automated fetches ("does not allow AI agents, scripts or other automated tools"), so its announcement and support pages could not be read for this note. It points such clients to its [public data](https://tradeskillmaster.com/public-data), which lists Forever as a game version.
- Region data for Forever is published, US and EU, refreshed 26 November 2026: [`forever/us/region/items.csv`](https://public-data.tradeskillmaster.com/forever/us/region/items.csv) and [`forever/eu/region/items.csv`](https://public-data.tradeskillmaster.com/forever/eu/region/items.csv) have the columns `marketValue, historical, avgSalePrice, saleRate, soldPerDay`, with real values. These correspond to the addon sources `DBRegionMarketAvg`, `DBRegionHistorical`, `DBRegionSaleAvg`, `DBRegionSaleRate` and `DBRegionSoldPerDay`; the mapping is inferred from the names, *unverified* in the addon.
- Realm data (`DBMarket`, `DBMinBuyout`, `DBHistorical`, `DBRecent`): Forever is realmless, one server per ruleset ([mein-mmo](https://mein-mmo.de/en/wow-forever-how-the-server-selection-works,1589193/), third-party), and no realm file could be found for guessed ruleset names. *Unverified* whether these sources are populated, and from what (the TSM Desktop App, or the player's own scans).
- Forever addons offer `DBMarket` as their default TSM string and AnotherLedger also lists `DBMinBuyout`, `DBRecent`, `DBHistorical` and `DBRegionMarketAvg` ([Options.lua#L459](https://github.com/mxhes/AnotherLedger/blob/10a14ae4f0ad8ce477565f008d112b140440f328/AnotherLedger/Options.lua#L459)). This shows they are offered, not that they return values.
- As the earlier note says, regional prices reach the addon through the TSM Desktop App ([2026-11-27-name-and-platform.md](2026-11-27-name-and-platform.md)).

## 7. Plan open question 4: `/kz`

- No Blizzard slash command starts with `/kz` in any of Forever's eleven locales (`SLASH_*` strings in [GlobalStrings](https://github.com/Ketho/BlizzardInterfaceResources/tree/e230342a476eb4ef484ba7b34adc0da6ecc6acc1/Resources/GlobalStrings)).
- None of the Forever addons above, nor those listed in the earlier note, use it; a web search found no addon using `/kz`. GitHub code search ignores the slash, so it can't search for the string itself.
- Verdict: no known conflict; *unverified* against the full CurseForge catalogue. Where two addons claim one command, which one wins is undefined ([Warcraft Wiki: Extracting info from a slash command](https://warcraft.wiki.gg/wiki/Extracting_info_from_a_slash_command)), so also register `/kezan`.
