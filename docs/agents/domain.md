# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain terminology.
- `docs/adr/` holds architectural decision records.

Before exploring a domain area, read the glossary and relevant ADRs.
The domain-modeling skill extends them when terminology or decisions are
resolved.

Use glossary terms consistently in code, tests, issues, and proposals.
Identify missing concepts for domain-modeling when needed.

Explicitly identify any proposal that conflicts with an existing ADR,
including the reason to reconsider that decision.

For scope, platform facts, price sources and the build order, consult
`docs/PROJECT_PLAN.md`, the plan of 27 November 2026.
